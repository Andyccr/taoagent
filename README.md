## 工作区检索、导航与系统优化

参考 [OpenBot 源码](https://github.com/nightly-labs/openbot/tree/a701c3d3b144e995d1b6b2de532f457f8eee9485)的工作区交互与状态设计，保留现有 Pi 内核、纯 HTML/CSS/JavaScript、逐项审批和可迁移的数据格式，未引入新的运行依赖。

- **历史搜索**：侧栏「搜索历史消息」或 Ctrl/⌘+Shift+F，跨活动对话或仅在当前对话查找。空格分隔的多个词须同时命中；结果按时间倒序分页，显示来源、作者、时间和高亮摘要，点击查看完整原文，支持打开原对话。原对话默认打开最近消息，旧消息原文在搜索弹窗查看。内部咨询、活动日志、已删除群聊和已移除成员的私聊不进入搜索。
- **状态导航**：侧栏可筛选全部、待处理、运行中和有更新的对话；待审批优先于运行、失败和未读状态。对话控制新增置顶入口，同类对话中置顶优先。置顶与已读版本保存在 `home/workspace-navigation.json`，多窗口合并更新，拒绝过期操作。第一次使用时，未查看过的历史对话也显示更新提示。
- **系统诊断**：设置 → 工作空间总览 → 系统状态与诊断，查看版本、Node 版本、运行时间、进程内存和运行数量，导出 JSON。诊断不含聊天、记忆、密钥、模型地址或本机目录；模型连通性仍通过设置中的模型检测核验。
- **资源与搜索性能**：静态 HTML、JavaScript、CSS 启动时预压缩，支持 gzip 与 ETag/304。历史搜索逐行读取 JSONL，结果集保持在一页大小，定期让出事件循环；每个服务最多同时运行两次搜索，关闭弹窗或开始新搜索会取消旧请求。已知凭据先脱敏再生成摘要，不截断或修改原始历史。

参考范围、接口、测试与局限见 [优化说明](OPENBOT-OPTIMIZATION.md)。启动方式不变；源码与发布包更新后需由用户重启当前服务才会生效。

## 群聊删除与无主题头脑风暴

**手动删除**：在群聊右上角「对话控制 → 删除群聊」，或「设置 → 成员与讨论」的群聊列表中点击删除。确认后，群聊退出活动列表，当前讨论停止，关联例行任务暂停。聊天、记忆、工作文件、草稿与审批回执均保留；可在「设置 → 成员与讨论 → 已删除群聊」恢复。恢复不会自动启用例行任务。已经执行的外部操作不会因删除群聊而撤销。

**让 Bot 删除**：直接告诉助手要删除哪个群。Bot 可用 `list_groups` 读取账户内群聊的名称、ID、模式和成员数量，不读取其他群的历史或记忆；用 `delete_group(groupId, reason)` 提出删除申请。当前群和 Bot 未加入的旧群都可以申请，但必须由你针对该目标逐项批准。审批显示群名与保留数据、停止执行、暂停例行任务的影响，并绑定群名称、成员和设置版本。配置改变会拒绝旧审批；已经完成的删除回执不会重复执行。

删除后，旧的待批操作失效，不能向群里发送新消息、继续旧任务、修改群模型或通过普通编辑恢复群聊。删除与恢复均更新生命周期版本，跨窗口的旧运行实例也不能因恢复而自动继续执行；需要继续时由用户重新发起或显式重试。恢复必须使用专用入口；默认团队初始化不会重新创建已删除的群。新增操作接口为 `DELETE /api/groups/:id`（JSON 请求体可包含 expected 与 reason）、`POST /api/groups/:id/archive` 和 `POST /api/groups/:id/restore`；已删除群列表在 `GET /api/groups/archived`，沿用本机与同源保护。

**不指定主题也能聊天**：新建或编辑群聊时，名称和「话题与约定」均可留空。留空名称自动显示「随便聊聊」或「头脑风暴」，并不会要求先补一个任务目标。自然讨论支持自由闲聊；选择「头脑风暴」时，默认先由两位成员独立发散，再按具体内容接话，其他成员按参与情况轮换初始机会。显式选择发言人或 @成员仍优先。

空白群聊提供「随便聊聊」和「无主题头脑风暴」开场按钮，点击只填入草稿，不会自动发送；也可以直接输入“大家随便聊聊”。成员可以提出观察、趣味问题、假设、跨领域联想，组合或转向彼此的想法，不强制总结、派工、收敛或达成一致。幻想与猜测须标明，发散内容不自动成为已验证事实。思考深度、并发和停止仍由原有预算与插话机制控制；脑暴旁听为推理模型提供最多4096输出 token，并受成员自己的输出上限约束。

完整回归、浏览器验收和真实无主题试验记录见本地 `VALIDATION-3.12.0.md`。原有群聊的名称、目标、模式、成员模型和四位核心 Bot 不会自动改写；需要时可以把已有群切换为头脑风暴。

## 讨论、协作与成员管理

当前工作空间按用户确认精简为四位核心成员：助手（main）、程序员、参谋、研究员。「我的团队」由助手首先接收用户消息，各专业成员可以彼此直接交流。23位其余成员从活动列表和执行路由中移除；个人规则、记忆、历史、模型配置及迁移原件保留，设置 → 成员与讨论 → 已移除 Bot 可恢复。精简前的成员和群配置保存在 `home/archive/team-curation-*/manifest.json`；恢复成员不会覆盖后来修改的群配置。

- **私聊咨询**：助手可用 `consult_agent` 实际调用另一位活动成员的模型，传入必要问题并取得回答。咨询使用独立记录，不转发原私聊、不注入双方个人记忆，也不递归执行工具；调用计入原轮次预算。需要实际操作的多人任务请在群中派工。
- **持续核对讨论**：`read_updates` 查看起草期间新完成的公开消息，节选用 `read_message` 分页读取。并行草稿仍不可见；历史和来源消息完整保留。公开追问只有收到针对原消息的实际回答才标为已回应；回应不等于争议已经解决。
- **验收与返工**：`assign_task` 可写 `acceptanceCriteria`，提供标准时默认需要独立验收。`complete_task` 提交结果；`review_task` 接受或要求返工。执行者不能自验收，只有派工者能要求返工，原结果保留在历史中。需验收的前置任务通过后，下游才开始；旧任务和明确不需验收的简单任务保持兼容。
- **恢复交接**：派工者可用 `reassign_task` 把未开始、尚未提交的任务交给当前成员，保留完整原指令、验收条件、依赖与原负责人。正在执行的任务须先停止，已提交结果不覆盖。`read_collaboration` 和对话控制展示开放问题、待验收任务及失去活动负责人的任务。
- **综合候选**：`record_reasoning(kind=synthesis)` 要关联至少两位成员的公开前提，说明 `novelty`（新组合带来的变化）和 `validation`（如何检验）。不能原样复制某个前提或使用已取代的版本；前提变化会把相关候选标为待复查。它保留可追溯的组合、分歧和修正，不能证明语义新颖性，也不把多人赞同、发言轮数或脚本测试通过称为涌现。
- **增删须批准**：Bot 的 `create_agent`、`delete_agent` 都进入现有逐项审批账本，批准前没有创建或移除效果。删除审批展示目标名称与影响，并绑定当时的身份和记忆版本；审批后目标变更会拒绝执行。主助手和发起操作的自己不能被删除。移除是可恢复的退出，不能用普通编辑或默认团队初始化偷偷恢复。手动操作有确认框；恢复后原始历史与记忆仍在。

源码、HTTP 流式协议、Pi 内核、预算、插话取消与本地审批机制继续使用。完整回归、模拟模型专项和浏览器验收记录见本地 `VALIDATION-3.11.0.md`；真实模型的讨论质量需要在实际任务中评估，系统不保证每次产生涌现。

## 工作台、技能与例行任务

侧栏「工作台」集中列出所有对话的待审批操作、待完成任务和中断工作；点击即可回到原对话查看操作详情或继续执行。共享技能与例行任务分别管理，均通过真实服务接口保存。

在「共享技能」中保存适用条件、完整步骤、验证方法与交付要求。所有成员可用 `list_skills` 分页检索已启用技能，用 `read_skill` 读取完整流程。技能按需读取，不把整个库塞入每次上下文；停用后模型不能再读取。点击「用于当前对话」仅向现有草稿追加技能引用，发送前可继续编辑。技能不能扩大工具权限。修改校验版本，保留原始版本，多窗口冲突会拒绝覆盖。

在「例行任务」中选择已有对话、填写工作要求与间隔，并明确勾选启用。默认暂停，最短5分钟；每次保存从完整间隔重新计时。执行使用原对话的成员、模型、记忆、运行预算和逐项审批；浏览器关闭后只要本地服务器仍运行，就可继续。**本机休眠、关机或服务器退出后不会执行**。重启后把错过的间隔合并为一次，执行前先持久化认领记录；其他实例不会重复执行同一认领。忙碌对话等待空闲，例行任务串行执行，运行记录和原对话保留成果。

每次最多10分钟（包括等待审批）；失败或中断自动暂停，避免连续消耗额度。服务意外退出时，不自动重放未确认的操作：恢复后标记中断并暂停，需查看原对话核对。取消勾选并保存可暂停后续执行，已经开始的工作需在原对话点停止。点击「在原对话准备试运行」会把工作追加为草稿，由你发送；不会提前认定测试通过。最近100次运行显示在工作台，完整记录仍保留在 `home/work.json`。

技能、例行任务、运行记录和编辑旧版本均存于 `home/`，随完整便携包迁移。执行反馈要求区分实际成果、验证证据和未解决事项。现有 Pi 内核、协作与记忆机制继续使用。设计参考 [Grok Bot 概览](https://docs.x.ai/grok-bot/overview)与[技能和例行任务](https://docs.x.ai/grok-bot/skills-routines-and-automations)；本地实现不包含云电脑、语音、示范教学、第三方连接器市场或事件 Webhook。

## 并发协作与源码改进

群聊采用事件驱动调度，默认同时两位成员思考，同一成员顺序处理事件。直接消息可在发送者完成前交给空闲接收者；任务的 `dependsOnTaskIds` 必须指向本群已有任务，结果实际完成后才调度依赖任务。无可执行工作时结束，不轮询模型、不强制轮流发言。群设置的「高级运行预算」可调并发数和模型调用数，完整配置见 [运行与验收说明](COLLABORATION-RELEASE.md)。

插话会取消旧生成与审批等待，保留中断草稿和已执行回执。取消不会撤销已经发生的外部操作。成员离群后不能继续执行或发布结果。每轮预算和每次上下文快照持久化；继续、重试或重启不会重置消耗。界面分开显示各事件的消息气泡，并区分并行起草、已完成和中断内容。

源码改进仍默认逐次审批。在「对话控制 → 源码改进与版本记录」中，可明确授权一个有目标、验收标准、验收测试、文件范围、调用/工具/token预留预算、迭代数和有效期的自动会话，再发送目标开始工作。停止按钮可随时撤销授权。授权不会延伸到 Shell、MCP、回滚等其他操作，它们仍需要原有审批。

模型用 `self_read` 分页查看源码和 SHA-256，省略路径可发现完整可修改范围和既有验收测试。可修改范围包含调度、存储、模型接入、服务接口和界面等16个文件；审批执行器、进化验证器、构建规则、依赖锁文件和既有测试保持保护。用 `self_evolve` 提交修改理由、预期收益、验收标准、既有验收测试路径和最多16个完整文件，无实际变化的候选会被拒绝。候选在 `home/evolution/<版本>/candidate` 中构建与测试，不复制 home 或凭据，并使用独立的 HOME、临时目录和白名单环境。先构建候选发布包，再执行预先指定的验收测试、完整回归和语法检查，全部通过才应用；校验期间改写受保护文件或源代码发生冲突会拒绝应用。验证结果、原文件、候选和版本记录均保留。

`self_history` 返回精简的版本与检查摘要，避免大段日志占满上下文。`self_inspect` 指定 `runId` 查看失败原因和检查索引，用 `checkIndex` 分页读取检查日志，或用 `path` 分页读取当时提交的候选源码；沿 `nextOffset` 可读取后续内容。在已授权范围和剩余预算内，模型可据此修正并提交下一候选。授权界面也展示可选文件与测试清单。

大文件可用 `changes: [{path, sha256, edits: [{before, after}]}]` 提交局部修改，或使用完整 `content`，两者不能混用。每个文件最多32次顺序替换，`before` 必须唯一匹配；哈希过期、匹配缺失或歧义会拒绝提交。局部修改先展开为完整候选，再执行相同验证并保留完整版本供回滚。小上下文模型接收的源码与日志页面会自适应缩小，保留 SHA-256 和准确的 `nextOffset`，避免节选截断翻页位置。

`self_history` 查看版本记录，`self_rollback` 经审批回滚且拒绝覆盖后续修改。中断应用可从版本记录执行显式恢复；活跃进程持有的源码锁不能强制清除。新版本需要用户重启，应用不会自动停止已有服务。候选目录是文件隔离工作目录，**不是操作系统安全沙箱**；测试代码仍有当前用户权限。开发依赖须已安装；便携目录可直接运行聊天，执行源码验证前需按锁文件安装依赖。

实测 provider tokens 与输入估算分开保存。缺少 usage 的调用显示未报告，不伪装成零消费；授权 token 预算使用保守请求预留。回归通过证明与这些检查兼容，不能独自证明收益；请用任务相关结果验证改进，也不能保证群体涌现或观点正确。

极简的本地多 Bot 群聊应用。Pi Agent Core 执行模型与工具循环，Taoagent 负责群聊、收件队列、任务、审批及可修正的共同记忆。服务只监听本机；所有个人状态保存在 `home/`。

## 直接启动

Windows：双击 **启动 Taoagent.cmd**。完整便携目录附带 Node 24.19 和已构建程序，无需安装 Node、npm、Docker 或数据库。启动后自动打开浏览器，控制台会显示地址；默认从 3467 开始寻找空闲端口，不会停止已有服务。关闭控制台或 Ctrl+C 退出。

首次使用：打开 **设置 → OpenCode Go**，填入 Go 账户 Key 并保存一次。六个默认 Bot 各自绑定模型，共用这份账户凭据。如果尚未配置 Go Key，请先完成这一步再进行真实模型聊天。已有其他模型、历史和记忆完整保留，不会自动改写成新模型。

群聊默认进入「我的团队」。群聊上方展开 **成员与模型**，可直接给每位成员换模型；「背景与提示词」可修改背景、要做的事情、提示词及记忆。顶部模型若选择统一模型，会明确覆盖成员选择；切回「按各 Agent 的模型设置」恢复独立模型。修改应用于下一次模型调用，不替换已在生成的回复。也可选择任一 Bot 私聊，单独修改其模型。

## 3.4 工作台与操作体验

界面提供五种可切换风格：极简工作台、暖纸书房、终端实验室、极光空间与黑白印记。它们分别调整界面层次、字形、圆角、边框和消息呈现；均支持浅色、深色和跟随系统。侧栏「外观」直接进入风格面板，右上角可快速切换明暗。成员与模型、公开论证、任务审批仍可在对话控制中展开。

主题色可与风格独立搭配：风格原色、陶土、苔绿、海蓝、鸢紫、玫瑰、琥珀、青瓷，以及自定义取色。自定义颜色会调整文字、按钮和柔和底色的对比度。面板提供实时聊天预览；还可选择跟随风格、衬线或等宽阅读字体，调整字号、间距、对话宽度和动效。偏好在当前浏览器保存；浏览器不允许持久保存时仍可在当前页面切换。恢复默认外观保留发送习惯，不改动聊天、模型或记忆。首屏在样式加载前恢复明暗与风格，减少主题闪烁；全部资源本地加载，无需外部字体或样式服务。

空白对话提供三种开场建议，点击只填入输入框；已有草稿会保留并追加建议，发送前可以继续修改。输入框下方可切换「Enter 发送」和「Enter 换行」，Ctrl/⌘+Enter 均可发送，Shift+Enter 换行。中文输入法选词时不会触发发送。消息支持安全的基础 Markdown、表格、代码块与复制；宽表格可横向滚动。

手机上通过左上角展开导航，点遮罩或 Esc 收起；打开聊天不会自动弹出键盘。弹窗具有标题，设置分类支持方向键，移动导航限制焦点在侧栏内。断开本地连接会明确提示，当前页面草稿保持可编辑；保存中显示处理状态。审批内容没有变化时不重建列表，用户手动折叠后不会反复抢回面板。更新后需重新启动本地程序，再刷新浏览器。

## 3.5 阅读与配置细节

发言增加成员头像和稳定配色；用户与成员消息均可复制或引用。引用会把完整可见正文和发言人追加到输入框，不覆盖已有草稿，也不会自动发送。输入框下方区分正在编辑、正在保存、已保存到本机和未保存；多窗口冲突时保留当前文字并提示对照，不把失败写入显示为保存成功。

设置新增「外观与输入」，可恢复跟随系统主题、选择标准或大字号、舒适或紧凑间距，以及发送快捷键；即时预览并在当前浏览器保存。模型列表可按名称、ID或协议筛选。群成员可搜索、查看选择数量，筛选不会取消勾选；选择2–12人后才可保存，负责人从已选成员中选择。编辑群聊时恢复该群原负责人，避免受到上一个群表单的影响。成员、群聊、个人资料和背景表单使用固定保存栏，方便手机和长表单操作。

## 3.6 并发输入与配置可靠性

草稿保存失败时可直接重试；另一窗口更新了同一草稿时，可点击「对照草稿」查看当前编辑与本机已保存版本，再选择保存当前版本。提交时再次检查版本，遇到新的修改会重新载入供对照；保存草稿不会发送消息。有尚未保存的编辑时，关闭或刷新页面会触发浏览器离开提醒，请先处理保存状态。

任务与审批默认展示最近操作，并始终保留更早的待审批、执行中和结果不确定的操作；可展开全部操作记录。长任务结果和工具回执明确标注节选，并可查看完整内容。外观与发送习惯在同一浏览器的其他窗口同步，不改动正在编辑的草稿。生成结束时尊重当前阅读或弹窗焦点，手机上不会自动唤起输入键盘。异常响应会给出可操作的提示；没有自动改进授权时点击停止也会正常返回结果。

发送和插话固定绑定点击时的对话、正文、成员和模型；请求返回时仅清空未被继续修改的原草稿。等待期间继续输入或切换聊天，都不会被旧响应清空；等待提交确认时的重复点击不会重复投递。切换聊天会立即清空旧工具输出并隐藏旧成员和审批控件，完整回执仍在原对话中。

全局资料保存与冲突检查在同一写锁中执行，旧版本仍备份；群模型切换也在锁内重读配置，只修改模型并推进群设置版本。过期窗口的选择返回冲突提示并恢复最新模型，旧群设置表单不能覆盖已更新的版本。连接检测为推理模型保留最多1024的输出额度，同时尊重模型配置的更小上限；检测只使用公开测试文本，不创建聊天历史。

## 3.7 操作流程修复

设置、成员资料和记忆窗口打开后立即显示载入状态；载入期间可关闭，晚到的响应不会重新打开或覆盖新窗口。失败时可原地重试。保存先取得完整表单值，再暂时保护相关控件，避免保存过程中改字段、切换范围或误关窗口；普通接口请求超过45秒会返回明确提示，整理历史单独允许更长时间。超时后需重新载入核对结果，不能据超时认定服务器一定未保存。

放弃修改、切换未保存内容和撤回记忆使用应用内确认框，默认保留编辑，Esc也会保留。模型编辑取消和切换都会检查未保存内容。工具面板现在浮层展开，不再挤掉聊天区域，可点外部或按Esc收起；@候选会在切换聊天或点外部时关闭。空消息禁用发送，等待接收时显示发送状态，点击停止可以取消尚在提交的请求并保留草稿；已接收的消息仍留在历史，可继续未完成成员。

记忆窗口将「背景与约定」独立折叠，背景与记忆分别保存，避免固定的「保存背景」按钮干扰记忆操作。成员、记忆范围、来源与历史查询忽略过期响应；载入新记忆期间保护旧编辑区，失败会恢复原选择。旧对话的整理操作绑定其原对话，不能误停新对话。手机短屏模式压缩顶部区域，保持输入框可见。

## 自主协作怎样工作

没有预设讨论阶段或必须轮流说话的顺序。默认负责人先接话；`@名字`、`@成员ID` 或 `@全体` 决定首批发言人。自然讨论中，成员用自己的模型判断是否要回答、追问细节、举例试探、补充约束、组合不同成员的思路或修正自己的说法。接话判断保留具体理由和准备推进的内容，正式回复再核对最新讨论；不要求每句话都有全新事实，也不把礼貌附和当作有用贡献。发言中的 `@成员` 和上一个对话对象会被优先考虑，但仍允许成员选择安静旁听。Bot 也可用 send_message 直接联系同事或派工；普通自然接话不依赖工具调用。

群设置可切换「自然讨论」与「定向协作」；后者仅处理点名和成员实际发送的协作消息。界面和 Bot 新建的群、默认团队启用自然讨论；旧群未设置模式时按自然讨论处理。默认每轮24次模型调用、8次旁听判断、每位成员最多4个发言事件、接话深度6。已去掉“同一成员最多检查两次”和隐藏的16事件截断；实际按本轮配置限制执行。高级运行预算可调往返深度、旁听次数、每人发言次数和总事件数。旧安装仅在群仍使用完整旧默认配置、属于自然讨论且没有正在运行时升级默认深度，保留自定义预算和历史轮次的预算。

正在判断是否接话时出现的新消息会保留为下一次待判断机会，同一成员待判断的消息合并到最新一条；不会因为成员正忙就直接丢失。已经看过并回应的内容不重复唤醒。自然接话保存所回应的消息ID和意图，聊天气泡可查看原消息。安静旁听不会发布凑数回复或生成共同记忆。队列结束、大家没有具体内容要说或达到预算时停止；用户可以随时插话。

自然语气不赋予成员现实身份或线下行动能力。未知人数、时间、经历和所在地应向用户确认或明确作为假设，不能为了把聊天接下去而编造。上述机制提供多次互动、不同意见和组合想法的条件，不能保证每次讨论都产生新的洞见。

群成员之间可直接沟通，无需经理中转。`list_group_members` 返回当前群成员与分工；通过 `create_agent(joinGroup=true)` 邀请的新专家可以在同一轮收到消息或派工。默认每群最多两位成员并发处理（可配置1–8位），发言与旁听共用并发位置；同一成员只处理一件事。成员发出定向消息后，空闲的接收者可立即开始回应，不必等待发送者结束整段工具循环。没有指定成员时仍由负责人先接话；输入 `@全体` 可让多位成员直接开始独立思考。每轮默认限制 16 条自主事件、6 次交接、每成员 4 次接收、24 次模型调用和 80 次工具调度。调用计数保存到本轮记录，暂停、继续和重启都不会重置；预算耗尽后需发送新一轮消息。自然讨论不做后台定时唤醒；用户启用的例行任务仅随本地服务运行，不提供关闭服务后继续运行的云任务。

每条公开回复最多提供两个旁听机会，优先轮转较少参与的成员；同一成员待处理的旁听机会合并到最新消息，已经纳入其回复的消息不再消耗判断调用。旁听上下文上限为16000字符，较长来源明确标为节选；正式回应仍使用正常上下文。仅赞同或重复时保持安静，不为了模拟热闹而强制发言。

界面同时显示各成员独立生成的气泡，以事件ID隔离交错文字；每个动画帧最多重绘一次该气泡。生成期间收到的新公开消息会留下来源记录，并标注「并行起草」，不能把这类独立意见当作已经互相核验。用户插话优先进入待处理队列，旧任务停止后续工具和模型调用，旧草稿保留为中断记录，不进入共同记忆；已经执行的外部操作不会撤销。审批按具体操作独立唤醒，实际写文件、命令和MCP等有副作用的操作在同一应用数据目录内串行执行。点击停止会等待所有正在处理的成员收尾，继续时保留已完成工作和预算。

支持「提出方案 → 另一成员给出反例 → 第三位改进方案 → 交回原作者修正」这样的自发交流闭环。成员的消息作为带来源的协作材料进入上下文，不会被提升为系统规则；调度规则和完整待处理消息一起计入上下文预算。公开成果保留在共同记忆中，未验证结论仍标为待验证。机制允许新认识在交流中形成，但不保证每次讨论都会产生涌现，也不把固定脚本测试当作真实模型的创造力证明。

3.1.0 增加议题、消息意图、证据引用和因果回复关系。成员可用 `send_message(intent=question/challenge/proposal/answer/revision)` 明确目的，用 `reply_message` 自动交回当前发送者，用 `read_discussion` 查看议题和待回应问题。不同议题独立跟踪；对同一收件人、同一议题、相同意图和证据的重复内容只返回已有状态，不新增唤醒；新增证据或不同意见仍可投递。页面进度展示消息意图与待回应问题数。「已回应」只表示关联回答已送达，不代表事实已验证或分歧已解决。完整设计、论文来源和验证边界见 [COMMUNICATION.md](COMMUNICATION.md)。

生成时可继续输入「插话」，消息立即保存，在有空闲处理位置时优先于尚未处理的 Bot 消息送达；原协作消息继续保留。点击「停止」暂停，之后选择「继续未完成成员」。完成的事件不重跑；失败事件使用当前模型重新处理，已经成功的工具回执会复用。对于硬中断时正在执行的外部操作，不能保证副作用未发生，会要求重新确认。

## 共同记忆

群体模式每条已完成的公开回复立即成为共享记忆，包含来源、作者和时间，初始标为「已共享·未验证」。所有成员下次都能检索，不等待同意才记住。`remember` 提炼事实、经验、决定和问题；`review_memory` 补充支持或质疑，支持、分歧、纠正和被取代版本均保留。独立成员支持只改变采用状态，不等于外部验证。

用户明确确认或手工修改优先。记忆支持查看来源、纠正、撤回、恢复和历史版本；旧摘要在记忆变更后失效，不会覆盖新认识。所有群聊模式不读取成员私聊或个人长期记忆，独立身份保留。私聊则使用所属 Bot 的个人记忆。上下文预算按字符估算，旧历史保留原文并可检索或手动整理摘要。

## 真实工具与审批

聊天上方的「任务与工具审批」显示待办、实际参数、执行状态和结果。

- `list_files` / `read_file`：只读本对话的 `home/workspace/<对话ID>/`，拒绝路径越界和链接。
- `write_file`：批准后写文件；写入有真实回执。
- `shell`：批准后执行本机 Shell，Windows 使用 cmd，目录在本对话 workspace；Shell 具备当前用户权限，并非系统沙箱。
- `run_cli`：真实调用 Git、GitHub `gh`、OpenCode `opencode`、Codex `codex`。CLI 需已安装并完成自己的登录配置，缺失时明确报错；不伪造结果。Windows 支持 npm 提供的 PowerShell/CMD 入口。
- `mcp`：设置底部可添加 stdio 或 HTTP MCP 服务。每次连接、列工具或调用前审批；完整握手和调用由 Pi MCP 执行。示例：`[{"id":"local","command":"your-mcp-server","args":[]}]`，或 `[{"id":"remote","url":"https://example.com/mcp","token":"..."}]`。令牌留空保留，删除服务需从数组移除该条。

文件修改、Shell、CLI、MCP 均需逐项批准，可拒绝。单次命令最多 120 秒、输出最多 256KB；模型收到节选，实际操作结果保留在审批账本。暂停会中断正在执行的本轮子进程，已发生的副作用不会回滚。

## 迁移、导出与源码

设置 → 迁移 → 下载完整便携包，包含程序、Windows Node、许可证及全部 `home/`。解压后即可在另一台 Windows 电脑启动。也可在所有对话结束后直接复制整个目录。包内包含账户 Key 和个人数据，请私密保存；对外发布源码须排除 `home/`、`backups/`、旧归档和日志。

## 极简界面与详细设置

日常界面仅保留成员导航、对话标题、输入框与右上角「…」入口。模型、发言对象、成员模型、记忆、协作论证、任务审批与运行进度集中在「对话控制」。待审批、运行中和待继续事项仍在顶部提供轻量提示。可用 Ctrl/⌘+B 收起导航、Ctrl/⌘+K 搜索、Ctrl/⌘+I 聚焦输入框。

「设置」改为可搜索的八类导航：常规、模型与账户、成员与讨论、个人信息与规则、工具与审批、外观与输入、数据与迁移。Ctrl/⌘+, 打开设置，Ctrl/⌘+Shift+, 打开对话控制。模型参数、独立身份和记忆、群协作规则、MCP 与迁移功能保留原有实际保存机制。外观增加对话宽度、封面建议、消息时间和操作按钮显示偏好，浏览器内即时保存。默认封面不展示建议卡片，消息时间隐藏；复制/引用可通过悬停、键盘焦点或触屏访问。

界面参考 Grok Bot 对持久成员、日常聊天与按需控制的分层方式，不包含其云电脑、语音或离线云端执行能力。
